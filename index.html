One-Command Install

Get RamShield running in under 2 minutes:

curl -fsSL https://ramshield.io/install.sh | bash

Or build from source:

cargo build --release --features full && cp target/release/ramshield /usr/local/bin/

Verify

curl -fsS http://127.0.0.1:9999/healthz && ./target/release/ramshield-cli status

Architecture

Basic loop: observe → detect → decide → block → expire

packet → NIC → XDP (kernel drop/flow-direct) → userspace enforcement → WAL → Store → IPC → CLI

When XDP disabled: proxy → IPC JSON → detection → WAL → Store → block at reverse proxy

Modules Overview

  • ramshield-config — TOML config, validation, env overrides
  • ramshield-types — IP networks, ConnectionEvent, IpRecord, CGNAT tiers
  • ramshield-detection — EWMA + CUSUM + Pulse + Subnet/ swarm detection
  • ramshield-enforcement — XDP projection, reconcile, block-state transition
  • ramshield-storage — WAL, checkpoint, snapshots, recovery
  • ramshield-mesh — CRDT Aworset sync (disabled in production)
  • ramshield-xdp — eBPF XDP engine (kernel dataplane)
  • ramshield-protocol — IPC JSON framing, HMAC auth, replay store

Where RamShield Wins: Sovereign, zero-subscription; kernel-level packet drops before socket allocations; crash-durable WAL; deterministic microsecond CUSUM drift detection; zero external feed dependencies.
Where It Loses: Cannot defeat ISP-uplink saturation (requires BGP FlowSpec/RTBH upstream); no community threat-intel DB; not an HTTP/WAF application-logic rules engine.
